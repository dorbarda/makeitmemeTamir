<objective>
Give the host the game's shape — how many rounds, how long to write, how long each rating step —
as three rows of preset buttons in the lobby, and make the server the authority on what a legal
value is. Non-hosts see the same settings read-only so nobody is surprised. Everything locks the
moment the game starts.

Purpose: LOBBY-06 asked for "host chooses rounds"; D-01 reads that as "host chooses the game's
shape", so a default that turns out wrong in front of the room is a one-tap fix rather than a
redeploy. LOBBY-07's start gate is hardened in the same pass because it is the other half of the
same lobby screen.

Output: a lobby the host can tune and start from, with a server that never trusts a single number
the client sent.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client socket -> `change-settings` handler | `key` and `value` are fully attacker-controlled; neither is coerced or trusted before `Room.changeSetting` sees them |
| `handlers.ts` -> `Room` | The handler never assigns `room.settings`; only `changeSetting` does, and only after `isPresetValue` |
| host identity | `hostId` lives on the room and moves only through Phase 1's automatic `transferHost()`; no client message names a host |
