<objective>
Reveal the round's memes one at a time, the same meme on every screen at once, each with its own
server-owned countdown that closes whether or not everyone rated it.

Two shapes matter here and both come straight from locked decisions. The rotation is built from
the *submissions*, not the players (D-08) — a person who never sent a caption is simply not in
it, so a round automatically gets shorter as people drop off. And a player who does not rate in
time casts nothing (D-10) — no default value is invented, and the engine records the eligible
rater count at close so Phase 4 can decide between a sum and an average with the data in hand.

Purpose: this is the second place a room can freeze on one person, and it happens once per meme —
roughly a dozen times a round. It has to close on its own every single time.

Output: a rating rotation that walks itself to the end of the round.
</objective>

Create `server/src/rooms/rotation.ts` as a pure module beside `Room.ts`, in the same style as
`gameSettings.ts`:
  - `buildRotation(submissions: ReadonlyMap<string, string>): string[]` — returns
    `[...submissions.keys()]`. Document why that is the whole implementation: a `Map`'s iteration
    order is insertion order, insertion happened at submission-arrival time in a single-threaded
    process, so arrival order is already a total order with no ties to break and no comparator to

    `eligibleAtClose = new Map<number, number>()` (stepIndex -> the eligible-rater count at the

    the ratings received and how many people could have rated, to choose between a sum and an

    start of each round.
  - Rewrite `closeWriting()`: build `this.rotation` once via `buildRotation(this.submissions)`;
    if `this.rotation.length < MIN_SUBMISSIONS_TO_RATE` go straight to `enterRoundEnd()` (plan

  - `private enterRevealBreak(nextStepIndex: number, delayMs: number): void` — sets
    `phase = "REVEAL_BREAK"`, sets `stepIndex = nextStepIndex`, and schedules
    `Date.now() + delayMs` with `enterRatingStep(nextStepIndex)` as the expiry. The break exists
    because an instant screen swap on a phone reads as having missed something (D-11): 3000 ms
    out of writing, 2000 ms between memes.
  - `private enterRatingStep(index: number): void` — sets `phase = "RATING"`, `stepIndex = index`,
    and schedules `Date.now() + this.settings.ratingSeconds * 1000` with `closeRatingStep` as the
    expiry. The step's clock starts when the step opens, so the break never eats into rating time.
  - `private closeRatingStep(): void` — records
    `eligibleAtClose.set(stepIndex, eligibleRaters(this.players, authorOfCurrentStep).length)`,
    then either `enterRevealBreak(stepIndex + 1, BETWEEN_MEMES_MS)` when another step remains, or
    `enterRoundEnd()`. It must be safe to reach only once per step: guard on
    `phase === "RATING"` at the top and return without effect otherwise, so a collapse that
    reschedules to the same instant the original timer would have fired cannot advance twice
    (the adjacency case).
  - `submitRating(playerId: string, stepIndex: unknown, value: unknown): SubmitRatingOutcome`
    where `SubmitRatingOutcome = { ok: true } | { ok: false; error: "WRONG_PHASE" |
    "CANNOT_RATE_OWN" | "ALREADY_RATED" | "RATING_OUT_OF_RANGE" }`, shaped like `RenameOutcome`.
    Refusal order: `phase !== "RATING"` or `stepIndex !== this.stepIndex` -> `WRONG_PHASE` (this
    is what makes a replayed or stale frame land nowhere, T-02-05); `playerId` is the current
    step's author -> `CANNOT_RATE_OWN`; `value` is not exactly 1, 2 or 3 ->
    `RATING_OUT_OF_RANGE`; that rater already has an entry for this step -> `ALREADY_RATED`. On
    success store the value, then call the early-finish check.
  - `private maybeCollapseRating(): void` — if every id returned by
    `eligibleRaters(this.players, authorOfCurrentStep)` has an entry in this step's ratings map,
    call `collapseDeadline(RATING_COLLAPSE_MS, closeRatingStep)`. Reuses plan 02-03's single
    shortening guard, so "never extends" holds here for free.
  - `snapshotFor(playerId)` — during `RATING` populate `ratingStep` with `index`,
    `total: this.rotation.length`, the current author's `caption` from `submissions`,
    `placeholderId` as the author's `joinedAt + 1`, `youAreAuthor`, `youMayRate` (eligible and
    not the author and not already rated), `youHaveRated`, `ratedCount` (this step's ratings map
    size) and `eligibleCount` (the live eligible count). `ratingStep` carries the CURRENT step's
    caption only — never the whole rotation's captions — and carries no author identity for
    anyone but the author themself. `ratingStep` is `null` in every other phase, including
    `REVEAL_BREAK`, so no caption rides along during a break either.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client socket -> `submit-rating` handler | `stepIndex` and `value` are fully attacker-controlled; the rater identity comes from `socket.data`, never from the payload |
| `handlers.ts` -> `Room` | The handler never touches `rotation`, `stepIndex` or `ratings`; only `submitRating` writes, and only after four ordered checks |
| server timer -> step advancement | Only `closeRatingStep`, reached from a timer, advances the rotation; no client message can move it |
| `Room` -> per-player snapshot | `ratingStep` exposes only the current step's caption and a personalized `youMayRate` / `youAreAuthor`; no other step's caption and no author identity travel |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Tampering | replaying `submit-rating` to stuff a meme's score | high | mitigate | Ratings are keyed `stepIndex -> raterId -> value`; a repeat from the same rater returns `ALREADY_RATED` before any write, and a `stepIndex` that is not the room's current step returns `WRONG_PHASE`, so a replayed frame lands nowhere |
| T-02-06 | Tampering | an out-of-range or non-integer rating value | high | mitigate | `submitRating` accepts exactly the literals 1, 2 and 3 and returns `RATING_OUT_OF_RANGE` for anything else, including floats, strings and `NaN`; the handler passes the raw value through so this is the only gate |
| T-02-16 | Elevation of Privilege | rating one's own meme | high | mitigate | `submitRating` refuses the current step's author with `CANNOT_RATE_OWN` server-side; the client's hidden buttons are presentation only |
| T-02-17 | Information Disclosure | the whole round's captions travelling during rating | high | mitigate | `ratingStep` carries the current step's caption only, and is `null` during `REVEAL_BREAK`; the full set of captions appears only in the `ROUND_END` view, after every step has closed |
| T-02-18 | Denial of Service | a step held open by a rater who never taps | high | mitigate | The step's `setTimeout` closes it regardless; `maybeCollapseRating` can only shorten, and `eligibleRaters` counts connected players only, so a departed player cannot even block the early finish |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs nothing — `files_modified` contains no `package.json` and no lockfile |
