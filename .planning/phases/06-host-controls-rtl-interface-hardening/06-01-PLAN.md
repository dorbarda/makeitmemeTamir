<objective>
Add the four host-only "break-glass" recovery actions to the server: skip the current round
(LIVE-04), remove a player (LIVE-05), end the game early (LIVE-06), and restart with the same
group (LIVE-07). Every action follows `Room.ts`'s existing `changeSetting`/`startGame` validation
order — identity first, then phase/state, then the mutation — and every discarded round's score is
simply never passed through `applyRoundScores`/`updateBestOfNight` (D-01), never computed as a
partial value.

Purpose: this phase's goal is host recovery tools for live mishaps during the party. This plan is
the server-side half — the actual state mutations and their wire contract — that Plan 06-02's
client UI calls into.

Output: four new `Room` methods (`skipRound`, `removePlayer`, `endGame`, `restartGame`), their
wire contract (4 new `CLIENT_EVENTS`, one new `RoundEndView` field), the matching socket handlers,
and a real-socket + bare-Room test suite proving each is host-only, discards scores correctly, and
never crashes on a bad or repeated input.
</objective>
