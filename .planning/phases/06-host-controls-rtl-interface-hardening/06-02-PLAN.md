Create `client/src/screens/round/HostControls.tsx`. **Resolves a UI-SPEC internal
inconsistency**: several passages describe the action being sent to the server before the
confirmation modal appears, while the Copywriting Contract's own "{action} בטוח?" ("are you
sure?") sentences and its explicit "Cancel: ... no server action is sent" rule only make sense as
a confirm-BEFORE-send gate. This component implements the confirm-before-send reading — a modal
that asks "are you sure?" after the action already fired would be actively misleading during a
live party, and only that reading is consistent with "Cancel... no server action is sent."

Shape: `type HostControlsProps = { snapshot: LobbySnapshot };`, a local `type PendingAction =
"skipRound" | "endGame" | "restartGame" | "removePlayer" | null;`. State: `pendingAction`
(`PendingAction`, default `null`), `removeListOpen` (`boolean`, default `false`), `targetPlayer`
(`{ id: string; name: string } | null`, default `null`), `error` (`string | undefined`, default
`undefined`). Return `null` immediately if `!snapshot.you.isHost` — defensive; `Round.tsx`'s own
gate (Task 3) already keeps this component from mounting for a non-host at all, matching
`Lobby.tsx`'s never-render (not CSS-hide) convention.

A `closeModal()` function resets `pendingAction`/`targetPlayer`/`error` to their defaults. A
`confirm()` function: if `pendingAction` is `null`, return; otherwise `const socket =
getSocket();`, register `socket.once(SERVER_EVENTS.error, onError)` (`onError` sets `error` to
`HEBREW_ERRORS[err.code]` then cleans up both listeners) and `socket.once(SERVER_EVENTS.state,
onState)` (`onState` calls `closeModal()` then cleans up) — the identical once-listener shape
`Lobby.tsx`'s `handleStartGame` already uses; then emit the correct event with `{}` for
`"skipRound"`/`"endGame"`/`"restartGame"`, or `CLIENT_EVENTS.removePlayer` with `{ targetPlayerId:
targetPlayer.id }` when `pendingAction === "removePlayer"` and `targetPlayer` is set.

Render `<section className="host-controls-panel">` with `<h2>{HEBREW_UI.hostControlsHeading}</h2>`
and `<div className="host-controls-grid">` holding exactly 4 `className="host-controls-button"`
buttons — skip (`onClick={() => setPendingAction("skipRound")}`), remove (`onClick={() =>
setRemoveListOpen(true)}`), end (`onClick={() => setPendingAction("endGame")}`), restart

phase (the UI-SPEC's own "populated state is the only state" rule; an invalid-for-this-phase tap
surfaces the server's `WRONG_PHASE` refusal in the error branch below exactly like any other
rejection, with no client-side phase-gating logic in this component at all).

When `removeListOpen` is `true`, render a `.host-modal-overlay` > `.host-modal`: compute `const

(`onClick={closeModal}`, `HEBREW_UI.cancelButton`) and a confirm button (`onClick={confirm}`,
