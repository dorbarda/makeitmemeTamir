<objective>
Three small, self-contained visual/UX fixes to the already-shipped Hebrew-RTL client: (1) the canvas
meme compositor's caption box auto-sizes to its wrapped text height and gets rounded corners, instead
of always drawing a fixed 360x100 black rectangle regardless of caption length; (2) the existing
"add caption box" button in the multi-box caption editor gets a clearly distinct dashed-border
affordance so players notice they can add up to 3 boxes; (3) a new decorative DVD-screensaver-style
bouncing hero-photo animation renders on the Lobby screen only.

Purpose: Fix 1 addresses a real visual bug the user flagged from a screenshot — a short caption like
"תמיר" left a large wasted black rectangle because the box height never depended on the text. Fixes 2
and 3 are UX/polish gaps noticed after the make-it-meme visual overhaul (quick task 260910-8yz)
shipped. All three are additive/behavior-preserving changes with no new npm dependencies, no changes
to gameplay/scoring logic, and no face/image auto-detection.

Output: `client/src/canvas/compositor.ts` draws each non-empty caption box with a height computed from
word-wrapped text (RTL-aware, `ctx.direction = 'rtl'` still set) and rounded corners (`ctx.roundRect`
where available, a manual arc-based fallback otherwise), still plain black/dark semi-transparent (no
gradient); `compositor.test.ts` is extended to cover auto-sizing, wrapping, and both corner-drawing
code paths. `WritingPanel.tsx` + `index.css` give the add-box button a distinct dashed "+" affordance.
A new `BouncingLogo.tsx` component, wired only into `Lobby.tsx`, animates a small bouncing hero photo
via `requestAnimationFrame`, cleaned up on unmount, with `pointer-events: none` so it never blocks taps.
</objective>

    `function wrapCaptionText(ctx: CanvasRenderingContext2D, text: string, maxWidth: number): string[]`

    `words.length === 0`, return `[""]`. Otherwise start `const lines: string[] = [];` and
    `let current = words[0];`; for each subsequent word (index `i` from `1` to `words.length - 1`),

    Otherwise, build a manual rounded-rect path and fill it: `ctx.beginPath(); ctx.moveTo(x + r, y);

    + height - r); ctx.arcTo(x + width, y + height, x + width - r, y + height, r); ctx.lineTo(x + r, y
    + height); ctx.arcTo(x, y + height, x, y + height - r, r); ctx.lineTo(x, y + r); ctx.arcTo(x, y, x
    + r, y, r); ctx.closePath(); ctx.fill();`.

    Export `function BouncingLogo()` (no props). Define `const LOGO_SIZE = 64;` (px — matches the CSS
    rule's `4rem` at the root `16px` font-size) and `const SPEED = 90;` (px/second) as module-level
    constants above the component. Inside the component: `const imgRef = useRef<HTMLImageElement>(null);`
    and `const stateRef = useRef({ x: 0, y: 0, vx: SPEED, vy: SPEED, last: 0 });` (a single mutable ref
    object holding position/velocity/last-frame-timestamp — deliberately NOT React state, so the
    animation never triggers a re-render).

    In a single `useEffect(() => { ... }, [])`: bail early if `imgRef.current` is null. Otherwise read
    `const state = stateRef.current;`, seed the starting position randomly within the viewport:
    `state.x = Math.random() * Math.max(0, window.innerWidth - LOGO_SIZE);`, `state.y = Math.random() *
    Math.max(0, window.innerHeight - LOGO_SIZE);`, `state.last = performance.now();`. Declare `let
    frameId: number;` and a `function tick(now: number)` closure: compute `const dt = Math.min((now -
    state.last) / 1000, 0.1);` (seconds since last frame, capped at `0.1`s so a backgrounded/resumed tab
    can't make the logo jump across the screen in one frame) and `state.last = now;`. Compute
    `const maxX = window.innerWidth - LOGO_SIZE;` and `const maxY = window.innerHeight - LOGO_SIZE;`
    fresh every frame (so a viewport resize/orientation-change is naturally picked up). Advance
    `state.x += state.vx * dt;` and `state.y += state.vy * dt;`. Bounce off each edge: `if (state.x <=
    0) { state.x = 0; state.vx = Math.abs(state.vx); } else if (state.x >= maxX) { state.x = maxX;
    state.vx = -Math.abs(state.vx); }` and the identical pattern for `state.y`/`state.vy`/`maxY`. Read
    `const el = imgRef.current;` and if it exists, set `el.style.transform =
    `translate(${state.x}px, ${state.y}px)`;` (direct DOM style mutation, not React state — this is the
    perf-critical 60fps path). Finally `frameId = window.requestAnimationFrame(tick);`. After defining
    `tick`, kick it off with `frameId = window.requestAnimationFrame(tick);` and return a cleanup
    function `() => window.cancelAnimationFrame(frameId);` from the effect — this is the required
